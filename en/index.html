Two ways forward for an institution

Both start from the Central Package

Ex Libris documents that an institution can inherit from the Central Package and upload its own package at the same time. The two are combined: anything only one package defines is used, and where both define the same thing, the institution's version wins.

Path A · Recommended starting point

Landing Page Configuration

Point-and-click setup of the landing page in Alma. Except for logo and favicon, everything else comes from the Central Package, so the view stays in step with the consortium.

What the IZ does

  • Ticks Enable configuration on the view's Landing Page tab.
  • Sets heading, background and “About the library” images, quick links (label, URL, icon), element order, announcement, login box and “About the library” text.
  • Text is multilingual through the Labels code tables. Announcements can be switched on and off, for example over a semester break.
  • Uploads a small package with logo and favicon. See the rule below.

Watch out for

  • The Landing Page tab only covers the landing page. Except for logo and favicon, everything else comes from the Central Package and defaults.
  • No custom layout. Colours come from the view's colour theme.
Path B

Own Customization Package

Full control over the local view, with the same tools the consortium office uses. For needs the landing page form can't meet.

What the IZ does

  • Starts from the starter package the consortium office provides to every institution, so nobody has to build on the template in Alma.
  • Adds or changes files: CSS, header, footer, landing page HTML, images, icons. The Central Package has no header, so a header is only possible this way.
  • Local CSS is added on top of the central CSS. Where rules conflict, the local rule wins.
  • Can replace the ready-made colour themes with its own Angular Material colour theme, built with customModule.
  • For new interface elements, builds Angular components with Ex Libris' customModule on GitHub.
  • Zips it as <institution_code>-<view_code> and uploads it to the view.

Watch out for

  • Needs HTML/CSS skills, and Node.js/Angular for components.
  • The IZ owns its code. Clarivate does not support institutions' code changes.
  • Anything the IZ redefines stops following central updates.
  • Local Angular components run alongside the consortium’s, but not if both build on the same element in the same position (before, after, top, bottom). Coordinate with the consortium office.

The one rule people miss

Your own logo and favicon always need a Customization Package

The Landing Page tab has no field for a logo or favicon. They are read only from files in a Customization Package. An IZ on path A that wants its own logo and favicon therefore uploads a small package with these two files, starting from the consortium office’s starter package. Everything else is still inherited from the Central Package.

Where things are managed

Who does what, and where in Alma

NZ · Consortium officeCentral Package for NDE: Configuration › Discovery › Display Configuration › Manage Customization Package, section NDE Central Package. Folder name <NZ_code>-CENTRAL_PACKAGE. Holds the Sikt logo, shared Angular components, the footer, CSS and shared images. The consortium office also provides a starter package that institutions use as the starting point for their own package.
IZ · InheritConfigure Views › [view] › Manage Customization Package, tick Inherit from Central Package.
IZ · Own package (B)Same tab, upload a ZIP in the Customization Package field. Start from the consortium office’s starter package.
IZ · Landing page (A)Configure Views › [view] › Landing Page, tick Enable configuration. Texts in Display Configuration › Labels.
IZ · Every viewColour theme (Color Theme – New UI on the Manage Customization Package tab), logo link (General tab), page title, banner heading and search box text (Labels: main.title, nde.landing.header, nui.search.placeholder).
