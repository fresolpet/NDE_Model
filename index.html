Begge starter fra Central Package

Ex Libris dokumenterer at en institusjon kan arve fra Central Package og samtidig laste opp sin egen pakke. De to slås sammen: Det som bare finnes i én av pakkene, brukes. Der begge definerer det samme, vinner institusjonens versjon.

Vei A · Anbefalt utgangspunkt

Landing Page Configuration

Oppsett av landingssiden med pek-og-klikk i Alma. Bortsett fra logo og favicon kommer alt annet fra Central Package, så visningen holder tritt med konsortiet.

Dette gjør IZ-en

  • Krysser av for Enable configuration i visningens Landing Page-fane.
  • Setter overskrift, bakgrunnsbilde og bilde for «About the library», hurtiglenker (tekst, URL, ikon), rekkefølge på elementer, kunngjøring, innloggingsboks og tekst for «About the library».
  • Tekstene blir flerspråklige gjennom Labels-kodetabellene. Kunngjøringer kan slås av og på, for eksempel i semesterferien.
  • Laster opp en liten pakke med logo og favicon. Se regelen nedenfor.

Vær obs på

  • Landing Page-fanen gjelder bare landingssiden. Bortsett fra logo og favicon kommer alt annet fra Central Package og standardoppsettet.
  • Ingen egen layout. Fargene kommer fra visningens fargetema.
Vei B

Egen Customization Package

Full kontroll over den lokale visningen, med de samme verktøyene som konsortiekontoret bruker. For behov som skjemaet for landingssiden ikke dekker.

Dette gjør IZ-en

  • Starter fra startpakken konsortiekontoret gir alle institusjoner, så ingen trenger å bygge på malen i Alma.
  • Legger til eller endrer filer: CSS, header, footer, HTML for landingssiden, bilder, ikoner. Central Package har ingen header, så en header er bare mulig på denne måten.
  • Lokal CSS legges oppå den sentrale CSS-en. Der regler kolliderer, vinner den lokale regelen.
  • Kan erstatte de ferdige fargetemaene med sitt eget Angular Material-fargetema, bygget med customModule.
  • Bygger Angular-komponenter med Ex Libris' customModule fra GitHub for nye elementer i grensesnittet.
  • Pakker alt som <institution_code>-<view_code> og laster det opp til visningen.

Vær obs på

  • Krever HTML- og CSS-kompetanse, og Node.js/Angular for komponenter.
  • IZ-en eier sin egen kode. Clarivate gir ikke støtte for institusjonenes egne kodeendringer.
  • Det IZ-en definerer på nytt, følger ikke lenger sentrale oppdateringer.
  • Lokale Angular-komponenter kjører sammen med konsortiets, men ikke hvis begge bygger på samme element i samme posisjon (before, after, top, bottom). Avtal med konsortiekontoret.

Egen logo og favicon krever alltid en Customization Package

Landing Page-fanen har ikke noe felt for logo eller favicon. De leses bare fra filer i en Customization Package. En IZ på vei A som vil ha egen logo og favicon, laster derfor opp en liten pakke med disse to filene, med konsortiekontorets startpakke som utgangspunkt. Alt annet arves fortsatt fra Central Package.
